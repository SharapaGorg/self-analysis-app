# Планирование дня и редизайн ревью — дизайн

Дата: 2026-10-09
Статус: на согласовании

## Цель

Превратить дашборд из «счётчика помодоров + свободное ревью» в инструмент
саморефлексии с планированием. Пользователь хочет:

1. Планировать день по задачам (помодоры на задачу) и видеть, где он
   медленнее/быстрее плана — сравнение план↔факт по каждой задаче.
2. Разложить ревью дня на три осмысленных поля: Ошибки / Победы / Выводы.
3. Добавить отдельную оценку ментального состояния («менталка»).
4. Отмечать социальный контакт за день (гулял с кем-то / был один).
5. Планировать следующий день заранее.
6. Для недели/месяца — автоматическую сводку по дням вместо ручного ревью.

Это личный локальный проект (Next.js 15 + better-sqlite3, один пользователь,
БД в `data.db`, не коммитится).

## Объём

### Входит
- Таблица `tasks` — задачи дня (план/факт помодоров + статус).
- День: 3-польное ревью, менталка (1–10 + текст), социальный тогл.
- Суммарные помодоры дня вычисляются из факта по задачам (с совместимостью
  со старыми днями без задач).
- Планирование любого дня, включая «план на завтра» (тот же редактор задач
  для даты следующего дня).
- Неделя/месяц: кнопка «Сгенерировать сводку» — LLM читает ошибки/победы/
  выводы дней периода и пишет сжатую сводку в 3 поля.
- Разовая миграция: 17 старых дневных `review` → разложить на 3 поля через
  Haiku.

### Не входит (YAGNI, отдельно потом при желании)
- Перенос незакрытых задач на следующий день.
- Менталка / задачи на уровне недели-месяца.
- Категории/теги/приоритеты задач.
- Напоминания/нотификации по плану.

## Модель данных

### Новая таблица `tasks`
```sql
CREATE TABLE IF NOT EXISTS tasks (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  date       TEXT NOT NULL,              -- YYYY-MM-DD, день, которому принадлежит задача
  title      TEXT NOT NULL,
  planned    INTEGER NOT NULL DEFAULT 0, -- запланированные помодоры, >= 0
  actual     INTEGER NOT NULL DEFAULT 0, -- фактические помодоры, >= 0
  done       INTEGER NOT NULL DEFAULT 0, -- 0/1
  sort_order INTEGER NOT NULL DEFAULT 0, -- порядок в списке дня
  updated_at TEXT NOT NULL,
  FOREIGN KEY (date) REFERENCES days(date) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_tasks_date ON tasks(date);
```

Строка `days` создаётся (upsert) при добавлении первой задачи на дату.

### Изменения в `days`
Новые колонки (через `ALTER TABLE ... ADD COLUMN` в миграции, идемпотентно):
- `mistakes    TEXT` — Ошибки
- `wins        TEXT` — Победы
- `conclusions TEXT` — Выводы
- `mental      INTEGER` — менталка 1..10, nullable
- `mental_note TEXT` — текст менталки
- `social      INTEGER NOT NULL DEFAULT 0` — 0 = один, 1 = был с кем-то

Старое поле `review` **сохраняется в схеме** (не удаляем), но UI его больше не
показывает — после миграции данные переезжают в три новых поля. Это
безопаснее, чем ронять колонку в SQLite.

### Суммарные помодоры дня
`days.pomodoros` остаётся колонкой ради обратной совместимости со старыми
записями и всей аналитикой (`lib/stats.ts`), которая её читает.

Правило (в `upsertDay`/репозитории задач): если у дня есть хотя бы одна
задача — `days.pomodoros` пересчитывается как `SUM(tasks.actual)` при каждом
изменении задач. Если задач нет — остаётся ручное значение (как у старых дней).
Так вся существующая статистика продолжает работать без изменений.

## Миграция схемы

`lib/db.ts::migrate()` дополняется:
1. `CREATE TABLE IF NOT EXISTS tasks ...` + индекс.
2. Для каждой новой колонки `days`: проверить `PRAGMA table_info(days)` и
   добавить недостающие через `ALTER TABLE days ADD COLUMN ...`.

Миграция идемпотентна и выполняется при открытии БД, как сейчас.

## Разовая миграция старого ревью (скрипт)

`scripts/migrate-reviews.ts` (запуск вручную, одноразово):
- Читает все `days` где `review` не пуст и (`mistakes`,`wins`,`conclusions`
  все пусты) — чтобы повторный запуск был безопасен.
- Для каждого вызывает Haiku (`claude-haiku-4-5-20251001`) с промптом:
  «Разложи этот дневной ретроспективный текст на три поля — ошибки, победы,
  выводы. Верни строго JSON `{"mistakes","wins","conclusions"}`. Что не
  относится к ошибкам/победам — помести в выводы. Не выдумывай, используй
  только текст.»
- Форсируем JSON-ответ (tool use / структурированный вывод); при сбое парсинга
  — весь текст кладём в `conclusions` как fallback и логируем дату.
- Пишет результат в новые колонки. `review` не трогаем (остаётся как архив).
- ~17 дней, ~10k символов — один проход, дёшево.

## LLM-интеграция

Новой зависимости в проекте нет. Добавляем:
- `@anthropic-ai/sdk` в dependencies.
- `ANTHROPIC_API_KEY` читается из `.env.local` (уже в `.gitignore` как
  `.env*.local`). Серверная сторона, ключ клиенту не отдаётся.
- Тонкий модуль `lib/llm.ts`: функция `summarizeReviews(days)` и
  `splitReview(text)` — обе дергают Anthropic Messages API со
  структурированным выводом. Модель — Haiku 4.5.
- На этапе реализации свериться со skill `claude-api` по актуальным id
  моделей и параметрам structured output.

Если ключ не задан — кнопка сводки показывает понятную ошибку, остальное
приложение работает (планирование/ревью от LLM не зависят).

## API

### Задачи
- `GET  /api/days/[date]/tasks` → `Task[]` (по `sort_order`).
- `POST /api/days/[date]/tasks` → создать задачу `{title, planned}`.
- `PUT  /api/tasks/[id]` → обновить `{title?, planned?, actual?, done?, sort_order?}`.
- `DELETE /api/tasks/[id]` → удалить.

Все мутации задач затем пересчитывают `days.pomodoros` для этой даты.

### День
- `PUT /api/days/[date]` расширяется полями `mistakes`, `wins`,
  `conclusions`, `mental`, `mental_note`, `social`. Поле `pomodoros` из
  тела игнорируется для дней с задачами (считается из задач); для дней без
  задач поведение как сейчас.

### Сводки недели/месяца
- `POST /api/weekly/[weekStart]/summary` → собирает дни недели, вызывает
  `summarizeReviews`, сохраняет результат в `weekly_reviews` (3 поля) и
  возвращает их.
- `POST /api/monthly/[month]/summary` → аналогично.

`weekly_reviews` / `monthly_reviews`: поле `review` заменяется на три
(`mistakes`,`wins`,`conclusions`) теми же ALTER-колонками; `quality` и `plan`
остаются как есть (ручные).

## Валидация (`lib/validate.ts`)
- `parseTitle` — непустая строка после trim.
- `parsePomodoros` уже есть (int >= 0) — переиспользуем для planned/actual.
- `parseBool` — 0/1 для `done`, `social`.
- `parseQuality` уже есть — для `mental`.

## UI

### Редактор дня (`components/DayEditor.tsx`)
Секции сверху вниз:
1. **Задачи дня** — новый компонент `TaskList`: строки `[title] [план] [факт]
   [✓готово] [удалить]`, кнопка «+ задача». Внизу итог: `план N → факт M`
   с подсветкой (факт > план — «медленнее», оранжевый; факт < план — зелёный).
   Ручной ввод `pomodoros` остаётся только для дней без задач (legacy).
2. **Качество дня** — как сейчас (`QualityPicker`).
3. **Менталка** — `QualityPicker` (1–10) + textarea.
4. **Ревью** — три textarea: Ошибки / Победы / Выводы (вместо одного).
5. **Тогл** «Был с кем-то / Один» — переключатель, пишет `social`.

### Планирование «на завтра»
Кнопка на дашборде/в навигации «План на завтра» → открывает тот же
`DayEditor` для даты `today+1`. Отдельного экрана-сущности нет — это тот же
редактор дня, просто на завтрашнюю дату (задачи можно завести заранее).

### Неделя/месяц (`app/reviews`, соответствующие формы)
- Убрать ручное поле `review`, показать 3 поля (read-only, из сводки).
- Кнопка «Сгенерировать сводку» → POST summary → заполняет 3 поля.
  Состояния: idle / генерация… / готово / ошибка.
- `quality` и `plan` остаются редактируемыми вручную.

## Тесты (vitest)
- Репозиторий задач: CRUD, пересчёт `days.pomodoros` = SUM(actual),
  каскадное удаление.
- Миграция схемы идемпотентна (повторный вызов не падает, колонки не
  дублируются).
- Валидаторы: `parseTitle`, `parseBool`.
- `splitReview`/`summarizeReviews`: LLM-вызов замокать; проверять сборку
  промпта, парсинг JSON и fallback при кривом ответе.
- Разовый скрипт миграции: на фикстуре из нескольких дней с замоканным LLM —
  раскладка в 3 поля и безопасность повторного запуска.
- Существующие тесты `lib/stats.ts` должны продолжать проходить без правок.

## Порядок реализации
1. Миграция схемы (tasks + колонки days) + типы.
2. Репозиторий задач + пересчёт pomodoros + тесты.
3. API задач и расширенный PUT дня.
4. UI редактора дня (задачи, менталка, 3 поля, тогл).
5. Кнопка «План на завтра».
6. `lib/llm.ts` + API сводок + кнопки на неделе/месяце.
7. Разовый скрипт миграции старого ревью, прогон на `data.db`.
