# Self-Analysis Dashboard — Design Spec

**Date:** 2026-09-27
**Status:** Approved for planning

## Purpose

Личный инструмент для отслеживания продуктивности. Пользователь вручную
вносит количество помодоро-сессий за каждый день (TickTick на бесплатном
тарифе не даёт истории глубже недели), пишет ревью дня/недели/месяца и
смотрит на дашборде динамику — насколько хорошо он работает в **количестве**
(помодоры) и в **качестве** (оценки из ревью).

Один пользователь, локальный запуск в браузере, приватные данные.

## Success Criteria

- Можно за секунды внести число помидоров за любой день через календарь.
- Ежедневное ревью (оценка 1–10 + текст), недельное ревью (оценка + итоги +
  планы на след. неделю), месячное ревью (оценка + итоги + планы на след.
  месяц) — все заполняются и перечитываются.
- Дашборд показывает динамику количества и качества с агрегациями по
  дню/неделе/месяцу, стрик относительно настраиваемой дневной цели.
- Данные переживают перезапуск; перенос на другую машину = копирование
  одного файла БД.

## Tech Stack

- **Next.js** (App Router, TypeScript) — фронтенд (React) + бэкенд (API routes /
  route handlers) в одном стеке.
- **better-sqlite3** — синхронный доступ к SQLite, файл `data.db` в корне проекта.
- **Recharts** — графики на дашборде.
- **Vitest** — юнит-тесты серверной логики.
- Запуск: `npm run dev`, открыть `http://localhost:3000`.

## Data Model (SQLite)

### `days`
Одна строка на дату. Держит счётчик помидоров И ревью дня.

| колонка      | тип     | примечание                              |
|--------------|---------|-----------------------------------------|
| `date`       | TEXT PK | `YYYY-MM-DD`                            |
| `pomodoros`  | INTEGER | по умолчанию 0                          |
| `quality`    | INTEGER | 1–10, nullable                          |
| `review`     | TEXT    | рефлексия дня, nullable                 |
| `updated_at` | TEXT    | ISO timestamp                           |

### `weekly_reviews`
Одна строка на неделю (неделя = ISO, начинается с понедельника).

| колонка       | тип     | примечание                              |
|---------------|---------|-----------------------------------------|
| `week_start`  | TEXT PK | дата понедельника недели, `YYYY-MM-DD`  |
| `quality`     | INTEGER | 1–10, nullable                          |
| `review`      | TEXT    | как прошла неделя, nullable             |
| `plan`        | TEXT    | планы на следующую неделю, nullable     |
| `updated_at`  | TEXT    | ISO timestamp                           |

### `monthly_reviews`
Одна строка на месяц.

| колонка       | тип     | примечание                              |
|---------------|---------|-----------------------------------------|
| `month`       | TEXT PK | `YYYY-MM`                               |
| `quality`     | INTEGER | 1–10, nullable                          |
| `review`      | TEXT    | итоги месяца, nullable                  |
| `plan`        | TEXT    | планы на следующий месяц, nullable      |
| `updated_at`  | TEXT    | ISO timestamp                           |

### `settings`
Одна строка (id=1) с конфигом.

| колонка       | тип     | примечание                              |
|---------------|---------|-----------------------------------------|
| `id`          | INTEGER PK | всегда 1                             |
| `daily_goal`  | INTEGER | цель помидоров в день, по умолчанию 8   |

**Портируемость:** вся БД — один файл `data.db`. Перенос = копирование файла.
Дополнительно кнопка «Скачать бэкап» экспортирует всю БД (или JSON-дамп).

## Date/Period Semantics

- **Неделя** начинается с **понедельника** (ISO). `week_start` = дата понедельника.
- **Воскресенье** — день недельного ревью (последний день ISO-недели).
- **Месяц** = `YYYY-MM`; месячное ревью «наступает» 1-го числа (за прошедший месяц).
- Все даты — в локальной таймзоне пользователя, формат `YYYY-MM-DD`.
- Логика границ недель/месяцев инкапсулирована в утилитах даты и покрыта тестами
  (особое внимание — переходы года и недели, пересекающие месяц/год).

## API (route handlers)

- `GET  /api/days?from=&to=` — записи дней в диапазоне (для календаря и дашборда).
- `PUT  /api/days/:date` — upsert записи дня (pomodoros / quality / review).
- `GET  /api/weekly/:weekStart` · `PUT /api/weekly/:weekStart` — недельное ревью.
- `GET  /api/monthly/:month` · `PUT /api/monthly/:month` — месячное ревью.
- `GET  /api/weekly` · `GET /api/monthly` — списки прошлых ревью.
- `GET  /api/settings` · `PUT /api/settings` — дневная цель.
- `GET  /api/stats?range=` — агрегированные метрики для дашборда (суммы, средние,
  стрик, дельты). Считаются на бэкенде, чтобы фронт не тянул все строки.
- `GET  /api/backup` — дамп БД для скачивания.

Все upsert-эндпоинты валидируют вход (диапазон оценки 1–10, дата в формате,
pomodoros ≥ 0).

## Pages / UI

Верхняя навигация: **Календарь · Ревью · Дашборд**. Плюс баннер-подсказка вверху.

### Календарь
- Сетка месяца, ячейка дня = число помидоров + цветовая заливка по `quality`
  (шкала красный→жёлтый→зелёный; серый если оценки нет).
- Клик по дню → боковая панель/модалка: степпер помидоров (+/−, ручной ввод),
  оценка 1–10, текстовое поле ревью. Сохранение через `PUT /api/days/:date`.
- Стрелки листания месяцев; выделение сегодняшнего дня.

### Ревью
- Вкладки **День / Неделя / Месяц**.
- Активная вкладка показывает форму текущего периода + список прошлых ревью
  (кликабельны для перечитывания/редактирования).
- Недельная форма: оценка + «как прошла неделя» + «планы на следующую неделю».
- Месячная форма: оценка + «итоги месяца» + «планы на следующий месяц».

### Дашборд
**Количество:**
- Столбчатый график помидоров по дням, переключатель диапазона 30/90/365 дней.
- Линия дневной цели поверх столбиков.
- KPI-плитки: помидоры сегодня / за неделю / за месяц / всего.
- Стрик: сколько дней подряд достигнута дневная цель.

**Качество:**
- Линия тренда оценок (дневные точки + недельные).
- Средняя оценка за неделю/месяц.

**Связка/динамика:**
- Дельта неделя-к-неделе и месяц-к-месяцу: изменение суммы помидоров (%) и
  средней оценки (пункты), с индикатором лучше/хуже.

## Reminder Logic (UI-подсказки)

Реальных пушей нет. Баннер вверху показывает, что «наступило» и не заполнено:
- Ревью дня за сегодня пустое → «Заполни ревью дня».
- Сегодня воскресенье и нет недельного ревью за текущую неделю → «Пора сделать
  ревью недели».
- Сегодня 1-е число и нет месячного ревью за прошедший месяц → «Ревью месяца».
Клик по баннеру ведёт на нужную форму.

## Component Boundaries

- **db layer** (`lib/db.ts`) — открытие SQLite, миграции/создание таблиц, seed
  настроек. Единственная точка доступа к better-sqlite3.
- **repositories** (`lib/repos/*`) — CRUD/upsert по каждой таблице; чистые
  функции над db-хендлом.
- **date utils** (`lib/dates.ts`) — границы недель/месяцев, ISO-week, форматирование.
  Не зависит ни от чего, полностью тестируется.
- **stats** (`lib/stats.ts`) — агрегации для дашборда поверх repositories; тестируется.
- **API route handlers** — тонкие, валидируют вход и зовут repos/stats.
- **UI-компоненты** — Календарь, формы Ревью, графики Дашборда; общаются с бэком
  через fetch к API.

Каждый модуль имеет одну ответственность и тестируется изолированно.

## Testing

- **Vitest** покрывает: `lib/dates` (границы периодов, переходы года), `lib/stats`
  (суммы/средние/стрик/дельты на фикстурах), repositories (upsert перезаписывает,
  диапазоны выборки), валидацию входа в API.
- Формы и графики проверяются вручную при запуске приложения.

## Out of Scope (YAGNI)

- Аутентификация / много пользователей.
- Облачная синхронизация, реальные push-уведомления.
- Автоматический импорт из TickTick.
- Мобильное приложение.

## Version Control

- `git init` в корне, публичная репа на GitHub.
- **`.gitignore` обязательно исключает `data.db` (и любые бэкапы/дампы БД)** —
  личные данные не должны попасть в публичный репозиторий. Код, спека и схема
  БД — коммитятся; данные — нет.
- В репе — README с инструкцией запуска; свежий клон создаёт пустую `data.db`
  при первом старте.
